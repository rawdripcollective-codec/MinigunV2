# MinigunV2 Terraform Stacks

Terraform configuration in this repository covers two distinct tracks:

- GitLab reference-architecture building blocks for AWS and GCP (EKS/GKE clusters, RDS/Cloud SQL/AlloyDB databases, Redis via ElastiCache/Memorystore, HAProxy/load balancers, Opensearch, Sidekiq, Gitaly, Rails, and supporting IAM/network/storage pieces), plus helper templates for custom EKS AMIs.
- An exported Google Cloud Application Template that deploys multiple Cloud Run services backed by BigQuery, AlloyDB, Redis, and a global HTTPS load balancer (see the `main.tf`/`outputs.tf` bundle generated by Google Cloud).

## Layout

- Core GitLab components: `network*.tf`, `security.tf`, `eks*.tf`, `gke*.tf`, `rds*.tf`, `cloud_sql*.tf`, `redis.tf`, `elasticache.tf`, `memorystore.tf`, `pgbouncer.tf`, `gitaly.tf`, `gitlab_rails.tf`, `haproxy.tf`, `opensearch*.tf`, `storage.tf`, `monitor.tf`, `sidekiq.tf`, and related Terraform files.
- Cloud Run application export: `main.tf`, `outputs.tf`, `providers.tf`, `versions.tf`, `terraform.tfvars`, and `variables.tf` (values come from the original Google Cloud template; adjust as needed).
- Templates: `templates/bootstrap.sh.tpl` and `templates/nodeadm.yml.tpl` hold the multi-part MIME userdata used when bootstrapping custom EKS nodes.
- Tests: `*.tftest.hcl` files are Terraform test suites that mock providers; update the `module source` paths inside them to point at your local module copy before running `terraform test`.

## Working with a stack

- Use Terraform >= 1.5 and configure AWS and/or Google Cloud credentials (environment variables or provider blocks) before planning.
- Work on one stack at a time to avoid mixing providers:
  1. **Cloud Run template:** keep the exported files together, then run `terraform init` and `terraform plan` in that directory.
  2. **GitLab reference architecture:** supply the expected input variables (prefix, regions, instance sizes, passwords, etc.) via `terraform.tfvars`/`*.auto.tfvars`, then run `terraform fmt` and `terraform test` when the tooling is available.
- The GitLab stack intentionally leaves variables undefined so you can tailor them to your environment; add the values required by the resources you enable.
